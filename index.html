2024 questions with answers

Two algorithms run in Tₐ(n) = 3n² + 20n and T_b(n) = 50 n log n + 200 n. Give the tight bound of each and say which grows faster.

Answer

Drop lower terms and constants: Tₐ = Θ(n²), T_b = Θ(n log n). Since n² / (n log n) = n / log n → ∞, Tₐ grows faster. For small n, Tₐ can still be cheaper because of the constant 50. With base-2 logs the curves cross near n ≈ 185.

New employee IDs are inserted one at a time into a sorted list by shifting larger IDs right. Give the best, average and worst case.

Answer

This is insertion sort's inner loop. Inserting one ID into a list of n IDs: best Θ(1) (new ID is the largest, no shifts), worst Θ(n) (new ID is the smallest, shift all), average Θ(n) (about n/2 shifts). Building a whole list of n IDs this way: best Θ(n), average and worst Θ(n²).

An algorithm splits a size-n problem into 4 subproblems of size n/4 and does n units of combine work. Write the recurrence and solve it by iteration with T(1) = c.

Answer

T(n) = 4T(n/4) + n. Expand:

T(n) = n + 4·T(n/4) = n + 4(n/4 + 4·T(n/16)) = 2n + 16·T(n/16) = 3n + 64·T(n/64) after k steps: k·n + 4ᵏ·T(n/4ᵏ)

Stop at n/4ᵏ = 1, so k = log₄ n and 4ᵏ = n. Then T(n) = n·log₄ n + c·n = Θ(n log n). Master check: a = 4, b = 4, n^(log₄ 4) = n = f(n), case 2.

For the selection-sort code (outer loop i, inner loop finds min_idx, then swap), state the best, average and worst cases and the time function.

Answer

The inner loop always runs, whatever the data, so comparisons are Σ (n − 1 − i) = n(n − 1)/2 in every case. Swaps are always n − 1. The only thing that varies is how often min_idx = j executes (never for sorted input, up to about n²/2 times for reverse sorted input), which changes the constant only.

Best, average and worst: T(n) = c₁·n(n−1)/2 + c₂(n−1) + (assignments), so Θ(n²) in all three cases.

Show that if f and g are monotonically increasing then so are f + g and f(g(n)). If both are also non-negative, show f·g is monotonically increasing.

Answer

Take m ≤ n. Then f(m) ≤ f(n) and g(m) ≤ g(n).

Sum: f(m) + g(m) ≤ f(n) + g(n).

Composition: g(m) ≤ g(n), and f is increasing, so f(g(m)) ≤ f(g(n)).

Product: with non-negative values, f(m)g(m) ≤ f(n)g(m) ≤ f(n)g(n). The first step multiplies f(m) ≤ f(n) by g(m) ≥ 0, the second multiplies g(m) ≤ g(n) by f(n) ≥ 0.

Use a recursion tree to bound T(n) = T(n/2) + n (the exponent on n was unreadable in the scan), then verify with the master theorem.

Answer

Each level has one node. Level i costs n/2ⁱ. The sum is n(1 + 1/2 + 1/4 + …) < 2n, so T(n) = Θ(n). The root dominates.

Master: a = 1, b = 2, watershed n^(log₂ 1) = 1. f(n) = n is polynomially larger. Regularity: f(n/2) = n/2 ≤ (1/2)·f(n). Case 3 gives Θ(n).

If your paper has n²: the levels cost n²/4ⁱ, the sum is (4/3)n², and the answer is Θ(n²) by the same case 3 argument.

The worst-case quicksort recurrence is T(n) = max over 0 ≤ q ≤ n−1 of (T(q) + T(n−q−1)) + Θ(n). Prove by substitution that T(n) = Ω(n²).

Answer

Let the Θ(n) term be at least d·n. Guess T(n) ≥ c·n² and assume it for smaller sizes.

T(n) ≥ max over q of ( c·q² + c·(n−q−1)² ) + d·n

The function q² + (n−q−1)² is convex in q, so its maximum on 0 ≤ q ≤ n−1 is at an end point. At q = 0 or q = n−1 its value is (n−1)². So

T(n) ≥ c(n−1)² + d·n = c·n² + (d − 2c)·n + c ≥ c·n² when c ≤ d/2

Hence T(n) = Ω(n²). Since quicksort is also O(n²), the worst case is Θ(n²).

2023 questions with answers

Prove transpose symmetry: f(n) = O(g(n)) if and only if g(n) = Ω(f(n)), and f(n) = o(g(n)) if and only if g(n) = ω(f(n)).

Answer

O and Ω: f = O(g) means there are c > 0, n₀ with 0 ≤ f(n) ≤ c·g(n) for n ≥ n₀. Divide by c: g(n) ≥ (1/c)·f(n) ≥ 0. That is the definition of g = Ω(f) with constant 1/c. Reverse the steps for the other direction.

o and ω: f = o(g) means for every c > 0 there is n₀ with f(n) < c·g(n) for n ≥ n₀. Put c' = 1/c, which also ranges over all positive numbers: g(n) > c'·f(n) for every c' > 0 eventually. That is g = ω(f). Reverse for the converse.

Derive the recurrence of binary search and solve it.

Answer

Compare the key with the middle element (constant work), then search one half of size n/2: T(n) = T(n/2) + Θ(1), T(1) = Θ(1). Iteration: T(n) = c + T(n/2) = 2c + T(n/4) = … = c·lg n + T(1). Master: a = 1, b = 2, n^0 = 1 = f, case 2. T(n) = Θ(lg n).

Show that a binary tree with n nodes has height at least ⌊lg n⌋. (The scan of the exact statement was unclear; this is the standard form.)

Answer

Level j of a binary tree has at most 2ʲ nodes. A tree of height h has at most 1 + 2 + … + 2ʰ = 2^(h+1) − 1 nodes. So n ≤ 2^(h+1) − 1, which gives h + 1 ≥ lg(n + 1). Since h is an integer, h ≥ ⌈lg(n+1)⌉ − 1 = ⌊lg n⌋. This is the tree-height fact used in the comparison sort lower bound.

Explain why comparison-based sorting is adopted more widely than linear-time sorting.

Answer
  • Counting and radix sort need integer or fixed-width keys. Bucket sort needs numbers spread evenly over a known range. Comparison sorts only need a comparison function, so they sort any ordered type.
  • Counting sort costs Θ(n + k) time and space, which is poor when the key range k is far larger than n. Radix sort has d passes and extra space too.
  • Quicksort and heapsort sort in place and have small constants, so they often beat the linear sorts on real data.
  • The linear sorts avoid the Ω(n lg n) bound only by assuming something about the keys.

2022 questions with answers

Use mathematical induction to show that T(n) = 2 for n = 2 and T(n) = 2T(n/2) + n for n = 2ᵏ, k > 1, has solution T(n) = n lg n.

Answer

Base: n = 2: T(2) = 2 = 2·lg 2.

Step: assume T(2^(k−1)) = 2^(k−1)·(k−1). Then

T(2ᵏ) = 2·T(2^(k−1)) + 2ᵏ = 2·2^(k−1)·(k−1) + 2ᵏ = 2ᵏ(k − 1) + 2ᵏ = k·2ᵏ = n lg n

True for all n = 2ᵏ, k ≥ 1. ∎

Prove that f(n) = Θ(g(n)) if and only if f(n) = O(g(n)) and f(n) = Ω(g(n)).

Answer

(⇒) f = Θ(g) gives c₁, c₂, n₀ with 0 ≤ c₁·g(n) ≤ f(n) ≤ c₂·g(n) for n ≥ n₀. The right inequality is f = O(g), the left is f = Ω(g).

(⇐) Suppose f ≤ c₂·g for n ≥ n₁ and f ≥ c₁·g for n ≥ n₂. Take n₀ = max(n₁, n₂). Both hold together, which is the definition of Θ. ∎

Analyse the worst-case time of quicksort and merge sort. When does the worst case usually happen?

Answer

Merge sort: T(n) = 2T(n/2) + Θ(n) for every input, so the worst case is Θ(n lg n).

Quicksort: worst case T(n) = T(n−1) + Θ(n) = Θ(n²). It happens when every partition is as unbalanced as possible: the pivot is always the minimum or maximum. With first or last element as pivot, that is an already sorted or reverse sorted array. All equal keys with a Lomuto partition behave the same. A random pivot makes it unlikely for any fixed input.

Is the statement "quicksort runs in Θ(n log n)" accurate?

Answer

Not as a blanket claim. Θ means a bound that holds for the algorithm's running time over all inputs, but quicksort's worst case is Θ(n²). The correct statements: best and average (or expected, with random pivots) time is Θ(n lg n); worst case is Θ(n²); overall O(n²) and Ω(n lg n).

Algorithm A splits into 5 subproblems of half size and combines in linear time. B solves 2 subproblems of size n − 1 and combines in constant time. C splits into 9 subproblems of size n/3 and combines in Θ(n²). Find each running time and choose one.

Answer
  • A: T(n) = 5T(n/2) + Θ(n). log₂ 5 ≈ 2.32 > 1, case 1: Θ(n^(lg 5)) ≈ Θ(n^2.32).
  • B: T(n) = 2T(n−1) + Θ(1). Iteration gives 1 + 2 + 4 + … + 2^(n−1) ≈ 2ⁿ: Θ(2ⁿ).
  • C: T(n) = 9T(n/3) + Θ(n²). log₃ 9 = 2, equal to the exponent of f, case 2: Θ(n² lg n).

Order for large n: n² lg n < n^2.32 < 2ⁿ. Choose C, because n^0.32 outgrows lg n and the exponential is far worse.

Design a linear-time deadlock detection algorithm. A system is deadlocked if processes form a cycle of dependencies. (2022)

Answer

Build a directed graph. Each process is a vertex. Add an edge P → Q if P is waiting for something Q holds. A deadlock is a cycle. Run depth-first search with three colors: white (not visited), gray (on the current recursion path), black (finished). If DFS meets a gray vertex through an edge, that edge closes a cycle, and the gray vertices from there form the deadlocked set.

Each vertex and each edge is examined once, so the time is O(V + E), which is linear in the size of the graph.

Describe a BFS-based algorithm for the connected components of a graph. (2023)

Answer

Keep a visited array. For each vertex that is not yet visited, start a BFS from it, give every vertex reached the same component label, and increase the label. Each BFS covers exactly one component.

Time O(V + E), since every vertex enters the queue once and every edge is scanned a constant number of times.

Is the minimum spanning tree unique? Does Kruskal always give the same one? (common follow-up)

Answer

If all edge weights are distinct, the MST is unique. With ties there can be several MSTs of the same total weight. Kruskal and Prim may return different ones depending on tie-breaking, but all have the same weight.

1 + r + r² + … + r^k = (r^(k+1) − 1)/(r − 1) (r ≠ 1) for 0 < r < 1 the infinite sum is 1/(1 − r)

A recurrence writes the cost of a problem of size n in terms of smaller copies. Merge sort: T(n) = 2T(n/2) + Θ(n). Two halves solved recursively, plus linear merge work.

Methods of complexity analysis

Four tools: substitution, iteration (recursion tree), master method, amortized analysis. CLRS Chapter 4 covers the first three, Chapter 16 the fourth.

Substitution method highlighted

🟣 Beginner Explanation

Substitution = mathematical induction for recurrences.
You GUESS the answer first, then PROVE it by mathematical induction. It's like saying "I think the answer is Θ(n lg n)" and then proving it formally.

📋 Easy Step-by-Step AlgorithmTemplate (always use this format on the exam):
  1. Guess: Assume T(n) ≤ c·f(n) for some constant c > 0.
  2. Inductive step: Assume T(k) ≤ c·f(k) for all k < n. Plug into the recurrence.
  3. Simplify: Show the result is ≤ c·f(n), choosing c appropriately.
  4. Base case: Verify T(1) ≤ c·f(1) for the chosen c.

Example: Prove T(n)=2T(n/2)+n is O(n lg n).
Guess: T(n) ≤ c·n·lg(n).
T(n) = 2T(n/2)+n ≤ 2·c·(n/2)·lg(n/2)+n = c·n·lg(n/2)+n = c·n·(lg n - 1)+n = c·n·lg n - c·n + n.
This ≤ c·n·lg n when c·n - n ≥ 0, i.e., c ≥ 1. ✓ Take c = 1.

Common mistake: Don't subtract lower-order terms at the wrong step. Always keep the inductive hypothesis EXACT.

Guess the answer, then prove it by induction. Three steps: guess, assume the bound for smaller sizes, show it holds for n (and check base cases).

Worked example

T(n) = 2T(⌊n/2⌋) + n. Guess T(n) ≤ c·n·lg n for some c > 0.

T(n) ≤ 2·c·⌊n/2⌋·lg⌊n/2⌋ + n ≤ c·n·lg(n/2) + n = c·n·lg n − c·n + n ≤ c·n·lg n whenever c ≥ 1

Base case: lg 1 = 0, so T(1) ≤ c·1·lg 1 fails. Start the induction at n₀ = 2 and check T(2), T(3) by hand, choosing c large enough. Therefore T(n) = O(n lg n).

When the guess is almost right: strengthen it

T(n) = T(⌊n/2⌋) + T(⌈n/2⌉) + 1. Guess T(n) ≤ cn. Then T(n) ≤ cn + 1, which does not give ≤ cn. The guess is true but the induction is too weak. Strengthen to T(n) ≤ cn − d:

T(n) ≤ (c⌊n/2⌋ − d) + (c⌈n/2⌉ − d) + 1 = cn − 2d + 1 ≤ cn − d for d ≥ 1

So T(n) = O(n).

Classic trap

Do not "prove" T(n) = 2T(n/2) + n = O(n) by assuming T(m) ≤ cm. You get cn + n = (c+1)n, and concluding ≤ cn is wrong. The constant must be the same one you assumed. Examiners test this.

Exam template

  1. State the guess with an explicit constant.
  2. Inductive hypothesis: true for all m < n.
  3. Substitute into the recurrence, simplify, and finish with ≤ c·g(n).
  4. Choose c and n₀, and check the base cases.

Iteration and recursion tree highlighted

Expand the recurrence repeatedly, spot the pattern, sum it. A recursion tree draws that expansion: each node shows the non-recursive cost of one subproblem. Sum each level, then sum the levels.

Example 1: T(n) = 2T(n/2) + n

level 0: n (1 node) level 1: n/2 + n/2 = n (2 nodes) level 2: 4 · n/4 = n (4 nodes) … level i: 2ⁱ · n/2ⁱ = n depth: lg n levels, each costing n → T(n) = Θ(n lg n)

Example 2: T(n) = T(n−1) + n by iteration

T(n) = n + (n−1) + (n−2) + … + 1 = n(n+1)/2 = Θ(n²)

Example 3: T(n) = 3T(n/4) + cn²

Level i has 3ⁱ nodes of size n/4ⁱ, costing (3/16)ⁱ · cn². The ratio 3/16 < 1 makes the sum geometric and dominated by the root: Θ(n²). Leaves contribute Θ(n^(log₄ 3)), which is smaller.

Example 4: unbalanced, T(n) = T(n/3) + T(2n/3) + n

Every level costs at most n. The longest path shrinks by 2/3 each step, so the depth is log_{3/2} n. Upper bound O(n lg n). The shortest path gives depth log₃ n, so the bound is tight: Θ(n lg n).

Rule of thumb for trees: root-heavy cost gives Θ(f(n)), equal cost per level gives Θ(f(n) lg n), leaf-heavy cost gives Θ(n^(log_b a)). These are exactly the three master method cases.

Master method highlighted

🟣 Beginner Explanation

The master method is a shortcut to solve recurrences of the form T(n) = aT(n/b) + f(n).
a = how many subproblems, b = how much smaller each subproblem is, f(n) = extra work to split and combine.
Compare f(n) with n^(log_b a) to determine which dominates.

📋 Easy Step-by-Step AlgorithmThree cases (memorise these):
  1. Case 1: f(n) is SMALLER than n^c (by a polynomial factor) → Answer: Θ(n^c)
      where c = log_b(a). The subproblems dominate.
  2. Case 2: f(n) is ABOUT THE SAME as n^c (× lg^k n, k≥0) → Answer: Θ(n^c × lg^(k+1) n)
      Both contribute equally.
  3. Case 3: f(n) is LARGER than n^c (by a polynomial factor) AND regularity holds → Answer: Θ(f(n))
      The extra work dominates.

  • T(n) = 2T(n/2) + n: c=log₂2=1, f=n=n¹ → same → Case 2 → Θ(n lg n) (merge sort!)

  • T(n) = T(n/2) + 1: c=log₂1=0, f=1=n⁰ → Case 2 → Θ(lg n) (binary search!)
  • T(n) = 7T(n/2) + n²: c=log₂7≈2.807, f=n² < n^2.807 → Case 1 → Θ(n^lg7) (Strassen!)

Amortized analysis not highlighted

Amortized cost is the average cost per operation over a worst-case sequence. It is not a probability average. A single operation can be expensive while the whole sequence is cheap.

MethodIdea
AggregateBound the total cost of n operations, divide by n.
AccountingCharge each operation a fixed amount. Unused charge is stored as credit on items and pays for later expensive steps.
PotentialDefine Φ(state) ≥ 0, Φ(start) = 0. Amortized cost = actual cost + ΔΦ.

Binary counter, k bits, n increments

Aggregate: bit 0 flips every increment, bit 1 every 2nd, bit i every 2ⁱth. Total flips < n·(1 + 1/2 + 1/4 + …) = 2n. Amortized cost per increment is O(1), not O(k).

Accounting: charge 2 per increment. One unit flips a 0 to 1, the other stays on that bit as credit. Every 1 to 0 flip is paid by that credit.

Potential: Φ = number of 1 bits. An increment that resets t trailing ones costs t + 1 and changes Φ by 1 − t. Amortized cost = (t+1) + (1−t) = 2.

Other standard examples

Stack with MULTIPOP: each element is pushed once and popped at most once, so n operations cost O(n), amortized O(1). Dynamic array with doubling: a resize copies m items but happens only after m cheap inserts, giving amortized O(1) per insert.

Linear-time sorting

Comparison sorts cannot beat n lg n. Counting, radix and bucket sort escape that limit by using the values themselves, not just comparisons. CLRS Chapter 8.

Proof of correctness highlighted

To prove an algorithm correct, show it terminates and that its output is a sorted permutation of the input. For loops, use a loop invariant: a statement true before each iteration.

Three parts of a loop invariant proof

  • Initialization: true before the first iteration.
  • Maintenance: if true before an iteration, still true before the next.
  • Termination: when the loop ends, the invariant gives the property you want.

Example: insertion sort

INSERTION-SORT(A, n)
for i = 2 to n
    key = A[i]
    j = i - 1
    while j > 0 and A[j] > key
        A[j+1] = A[j]
        j = j - 1
    A[j+1] = key

Invariant: at the start of each iteration for index i, A[1..i−1] holds the original first i−1 elements in sorted order.

Initialization: i = 2, so A[1..1] is one element, trivially sorted.

Maintenance: the while loop shifts elements larger than key one step right and drops key into the gap. The prefix A[1..i] is the same elements, sorted.

Termination: the loop ends with i = n + 1. The invariant says A[1..n] is the original array, sorted.

Correctness of counting sort and radix sort

Counting sort: after the prefix-sum pass, C[v] equals the number of elements ≤ v, so the last copy of value v belongs at position C[v]. Scanning A right to left and decrementing places equal values in their original order, so the sort is stable.

Radix sort: induct on the digit position d (from least significant). Claim: after pass d, the array is sorted by the lowest d digits. Pass d+1 sorts by digit d+1. Items with different digit d+1 end in the right order. Items with equal digit d+1 keep their previous relative order because the digit sort is stable, and that order was already correct by the induction hypothesis. Stability is the whole proof.

Lower bound on comparison sorting highlighted

Theorem

Any comparison sort needs Ω(n lg n) comparisons in the worst case.

Proof (decision tree):

  1. Model the algorithm as a binary tree. Each internal node is a comparison aᵢ : aⱼ. Each leaf is one output permutation.
  2. Every one of the n! input orderings must reach a different leaf, so the tree has at least n! leaves.
  3. A binary tree of height h has at most 2ʰ leaves. So n! ≤ 2ʰ, hence h ≥ lg(n!).
  4. n! ≥ (n/2)^(n/2), because the top n/2 factors are each at least n/2. So lg(n!) ≥ (n/2)·lg(n/2) = Ω(n lg n).
  5. The height h equals the worst-case number of comparisons. ∎

Consequence: merge sort and heapsort, both O(n lg n), are asymptotically optimal comparison sorts. Linear-time sorts avoid the bound because they are not comparison sorts.

Counting sort highlighted

🟣 Beginner Explanation

Imagine counting votes. You have papers marked 1–5. Instead of sorting them by comparing pairs, you just count how many 1s, 2s, 3s, etc. Then you write them out in order. That's counting sort! It never compares two elements — it just counts.

📋 Easy Step-by-Step Algorithm
  1. Phase 1 — Count: Make an array C of size k+1, all zeros. For each number A[i], do C[A[i]]++. Now C[v] = how many times v appears.
  2. Phase 2 — Prefix sums: For i = 1 to k, do C[i] = C[i] + C[i-1]. Now C[v] = how many numbers are ≤ v. This tells you WHERE in the output each v should end up.
  3. Phase 3 — Place (right to left for stability): For j = n down to 1, put A[j] at position B[C[A[j]]], then decrement C[A[j]].

Example: A=[2,5,3,0,2,3,0,3], k=5
Count: C=[2,0,2,3,0,1] (two 0s, zero 1s, two 2s, three 3s, zero 4s, one 5)
Prefix: C=[2,2,4,7,7,8]
Output: [0,0,2,2,3,3,3,5] ✓

Why right to left? It keeps equal elements in their original order = STABLE.

Input: n integers in 0..k. Count occurrences, turn counts into positions, place each element.

COUNTING-SORT(A, n, k)
let B[1..n] and C[0..k] be new arrays
for i = 0 to k:  C[i] = 0
for j = 1 to n:  C[A[j]] = C[A[j]] + 1      // count
for i = 1 to k:  C[i] = C[i] + C[i-1]       // C[i] = # elements <= i
for j = n downto 1:                         // right to left = stable
    B[C[A[j]]] = A[j]
    C[A[j]] = C[A[j]] - 1
return B

  • Stable. Not in place. Not comparison-based.

Radix sort highlighted

🟣 Beginner Explanation

Imagine sorting phone numbers digit by digit. First sort by the last digit, then by the second-last, all the way to the first digit. If you use a stable sort at each step, the final result is fully sorted. The key insight: sort from LEAST significant to MOST significant digit.

📋 Easy Step-by-Step Algorithm
  1. Find d = number of digits in the largest number.
  2. For i = 1 to d (start from ones place, then tens, then hundreds...):
      Sort the whole array using STABLE counting sort on digit i only.

After ones: 720, 355, 436, 457, 657, 329, 839

Bucket sort highlighted

🟣 Beginner Explanation

Imagine sorting exam scores from 0.0 to 1.0. Make 10 "buckets": 0.0–0.1, 0.1–0.2, ..., 0.9–1.0. Throw each score into its bucket. Sort each small bucket (with insertion sort — fast because buckets are small). Collect them all. If scores are spread out uniformly, each bucket gets only a few scores — very fast!

📋 Easy Step-by-Step Algorithm
  1. Create n empty buckets (lists).
  2. For each element A[i]: put it into bucket ⌊n × A[i]⌋. (Works for values in [0,1).)
  3. Sort each bucket with insertion sort (or any stable sort).
  4. Concatenate buckets 0, 1, 2, ..., n-1.

When is it fast? When inputs are spread evenly — each bucket gets ~1 element, so sorting each bucket is O(1).
When is it slow? All elements in one bucket → O(n²) insertion sort on that bucket.

Assume inputs are drawn uniformly from [0, 1). Split the range into n equal buckets, drop each number into its bucket, sort each small bucket (insertion sort), concatenate.

BUCKET-SORT(A, n)
let B[0..n-1] be an array of empty lists
for i = 1 to n:  insert A[i] into list B[floor(n * A[i])]
for i = 0 to n-1: sort list B[i] with insertion sort
concatenate B[0], B[1], ..., B[n-1]

Facts for the exam

  • Expected time Θ(n) under uniform input. Let nᵢ be the size of bucket i. Then E[nᵢ²] = 2 − 1/n, so the expected total insertion-sort cost is Θ(n).
  • Worst case Θ(n²) if everything lands in one bucket.
  • Stable if the bucket sort is stable. Needs extra space Θ(n).

Median finding and selection not highlighted

Selection finds the i-th smallest element. The median is the case i = ⌈n/2⌉. Sorting solves it in Θ(n lg n). Selection does it faster.

Randomized select (expected Θ(n))

Partition around a random pivot (same PARTITION as quicksort). If the pivot lands at rank q, recurse into only the side that holds rank i. Only one side is searched, so the expected cost is n + n/2 + n/4 + … = O(n). Worst case Θ(n²).

Example: 3rd smallest of [7, 2, 9, 4, 1, 8, 3]. Pivot 4 gives low side {2,1,3} (3 elements), pivot rank 4. We want rank 3, so search the low side only.

Median of medians (worst case Θ(n))

  1. Split into groups of 5. Find each group's median (constant time per group).
  2. Recursively find the median x of those ⌈n/5⌉ medians.
  3. Partition around x.
  4. Recurse into the side that holds rank i.

At least about 3n/10 − 6 elements are less than x, and the same number greater. So the recursive call has size at most 7n/10 + 6:

T(n) ≤ T(⌈n/5⌉) + T(7n/10 + 6) + O(n)

Since 1/5 + 7/10 = 9/10 < 1, substitution gives T(n) = O(n). With groups of 3 the fractions become 1/3 + 2/3 = 1 and the bound is lost, giving n lg n. This is a favourite short question.

🔁 REPEATED QUESTION — asked in multiple years

🟣 Beginner Explanation

Imagine splitting a deck of cards in half, sorting each half separately, then carefully merging the two sorted halves. Keep splitting until you have single cards (already sorted!), then merge pairs, then groups of 4, etc. Unlike quicksort, the hard work is in the MERGE step, not the split.

📋 Easy Step-by-Step AlgorithmEasy 3-step idea:
  1. DIVIDE: Split array down the middle. q = ⌊(p+r)/2⌋.
  2. CONQUER: Recursively sort the left half A[p..q] and right half A[q+1..r].
  3. COMBINE (MERGE): Copy left half to L[], right half to R[]. Compare L[i] and R[j]; take the smaller one into A. Repeat until all placed.
Why it's always Θ(n lg n)? Every split makes 2 halves (so depth = lg n levels). Each level does n total work in the merge step. n × lg n = Θ(n lg n).

Convex hull: Graham scan and Quick Hull highlighted

🟣 Beginner Explanation

Convex hull = the rubber-band outline around a set of points.
Imagine pushing pins into a board at each point, then stretching a rubber band around ALL pins and releasing it. The pins the rubber band touches are the convex hull.

📋 Easy Step-by-Step AlgorithmGraham Scan (easy steps):
  1. Find the lowest point p0 (bottom-most, left-most if tie). This is always on the hull.
  2. Sort all other points by polar angle around p0 (counter-clockwise). Ties: keep closer point first.
  3. Push p0 and the first two sorted points onto a stack.
  4. For each remaining point p:
      While the top two stack points + p make a RIGHT turn (or are straight): POP the top.
      Push p.
  5. Stack = the convex hull in counter-clockwise order.

Left turn test: cross(a,b,c) = (b.x-a.x)(c.y-a.y) - (b.y-a.y)(c.x-a.x) > 0 means left turn (keep). ≤ 0 means right turn or straight (pop).

Quick Hull

Quick Hull is divide and conquer in the style of quicksort.

  1. Find the leftmost point A and the rightmost point B. Both are on the hull. The line AB splits the points into an upper set and a lower set.
  2. For the upper set, find the point C farthest from line AB. C is on the hull.
  3. Points inside triangle ACB cannot be on the hull. Discard them.
  4. Recurse on the points outside line AC and on the points outside line CB. Do the same for the lower set.

Greedy algorithms

At every step take the choice that looks best right now, and never undo it. This works only when the problem has two properties. CLRS Chapter 15 (greedy), Chapter 21 (spanning trees), Chapter 22 (shortest paths).

Greedy algorithm properties highlighted

Greedy choice property

A globally optimal solution can be reached by making a locally optimal choice. You never need to look back or compare with other choices.

Optimal substructure

After the greedy choice, what remains is a smaller instance of the same problem. The optimum of the whole is the choice plus the optimum of the rest.

Standard proof: exchange argument

  1. Take any optimal solution O.
  2. If O already contains the greedy choice g, stop.
  3. Otherwise swap some element of O for g. Show the new solution is still feasible and no worse.
  4. So some optimal solution contains g. Apply the same argument to the remaining subproblem, by induction.

Fractional knapsack highlighted 🔁 2 YEARS

⚠ 2022 + 2023: Greedy fractional knapsack with exchange argument proof

🟣 Beginner Explanation

Like 0/1 knapsack, but you CAN take fractions of items.
Imagine items are liquids or sand — you can take half a litre, or 0.3 kg. This makes greedy work! Always take as much as you can of the most valuable-per-kg item first.

📋 Easy Step-by-Step AlgorithmEasy greedy algorithm:
  1. Calculate value/weight ratio for each item.
  2. Sort items by ratio (highest first).
  3. For each item in sorted order:
      If the whole item fits (w[i] ≤ remaining capacity): take all of it.
      Else: take a fraction = (remaining capacity / w[i]). Stop.

Example: W=50, items=(60,10), (100,20), (120,30)
Ratios: 6, 5, 4. Sort: item1, item2, item3.
Take item1 (10kg, value 60). Remaining = 40.
Take item2 (20kg, value 100). Remaining = 20.
Take 20/30 of item3 (value = 120×20/30 = 80). Remaining = 0.
Total value = 60+100+80 = 240

Why greedy works here but NOT for 0/1: In fractional, you can always "fill in" with the best ratio item. In 0/1, you might need to leave the highest-ratio item out to fit a better combination.

  • 2023: Job sequencing with deadlines (separate topic but same paper section).
  • 2022 + 2023: Fractional knapsack, n=4, W=20. List all feasible solutions, find the greedy optimum, prove greedy works by exchange argument.

Proof summary: Take any optimal solution. If it doesn't take as much of the highest-ratio item as possible, swap some other item's weight for it. The value doesn't decrease (ratio is highest). Repeat until the greedy solution is reached.

Items have value vᵢ and weight wᵢ. The bag holds weight W. You may take any fraction of an item. Maximize the total value.

FRACTIONAL-KNAPSACK(v, w, W)
sort items by v[i]/w[i], largest first
for each item in that order
    if w[i] <= remaining capacity: take all of it
    else: take the fraction (remaining / w[i]) and stop

Worked example, W = 50

Items (value, weight): (60, 10), (100, 20), (120, 30). Ratios 6, 5, 4. Take item 1 (10), item 2 (20), then 20 of the 30 units of item 3: value 60 + 100 + 120 × 20/30 = 240.

The 0/1 version with the same ratio rule would take items 1 and 2 only (value 160) and could not fit item 3. The true 0/1 optimum is items 2 and 3, value 220. So greedy is wrong for 0/1 and correct for the fractional version.

Proof that fractional knapsack has the greedy choice property

Order items by ratio so item 1 has the largest v/w. Let O be an optimal solution that takes less of item 1 than it could, so it takes x₁ < min(1, W/w₁).

  1. The bag in O must be full. Otherwise add more of item 1 and improve it, a contradiction.
  2. So O holds some weight of other items. Pick weight δ of an item k in O and replace it with weight δ of item 1.
  3. The value changes by δ(v₁/w₁ − vₖ/wₖ) ≥ 0, since item 1 has the highest ratio.
  4. The new solution is feasible and no worse, and it takes more of item 1. Repeat until item 1 is taken as much as possible.

The rest of the bag is a smaller fractional knapsack with capacity reduced by what item 1 used, which gives optimal substructure. ∎ Time O(n lg n), dominated by the sort.

🟣 Beginner Explanation

You have jobs, each taking 1 hour. Each has a deadline and a profit. You want max profit.
Think of it as scheduling: you have time slots 1, 2, 3... A job with deadline 3 must be done by slot 3. You want to pick and schedule jobs to earn the most money.

📋 Easy Step-by-Step AlgorithmEasy greedy algorithm:
  1. Sort jobs by profit (highest first).
  2. Create a schedule array of size = max deadline, initially empty.
  3. For each job (in profit order):
      Find the latest free slot s where s ≤ deadline.
      If found: put this job in slot s.
      If not found: skip this job (we can't fit it).

Example: Jobs a,b,c,d,e with deadlines 2,1,2,1,3 and profits 100,19,27,25,15
Sort by profit: a(100,d=2), c(27,d=2), d(25,d=1), b(19,d=1), e(15,d=3)
Job a: latest free slot ≤ 2 = slot 2. Schedule: [_,a,_]
Job c: latest free slot ≤ 2 = slot 1. Schedule: [c,a,_]
Job d: latest free slot ≤ 1 = slot 1, but taken. Skip.
Job b: deadline 1, slot 1 taken. Skip.
Job e: latest free slot ≤ 3 = slot 3. Schedule: [c,a,e]
Profit = 27+100+15 = 142

Each job takes one unit of time, has a deadline dᵢ and a profit pᵢ paid only if the job finishes by its deadline. Only one job runs at a time. Choose and order jobs for maximum profit.

JOB-SEQUENCING(jobs)
sort jobs by profit, largest first
for each job
    find the latest free slot s with s <= its deadline
    if such a slot exists: put the job in slot s     // keeps earlier slots free
    else: reject the job

Worked example

Jobs a, b, c, d, e with deadlines 2, 1, 2, 1, 3 and profits 100, 19, 27, 25, 15. Sorted by profit: a (100), c (27), d (25), b (19), e (15).

  • c, deadline 2: slot 2 is taken, so slot 1.
  • d, deadline 1: slot 1 is taken, reject. b, deadline 1: reject.

⚠ 2024: Build Huffman tree for A=7, B=5, C=10, D=25, E=45

🟣 Beginner Explanation

Huffman coding gives shorter codes to more frequent characters — like Morse code.
E (most common letter in English) has the shortest Morse code (·). Huffman does the same mathematically.
It's used in ZIP files, JPEG images, and MP3 audio. The result is a binary tree where frequent characters are near the top (short code) and rare characters are near the bottom (long code).

📋 Easy Step-by-Step AlgorithmEasy algorithm (greedy — always merge the two smallest):
  1. Put all symbols with their frequencies into a MIN-priority queue (smallest frequency first).
  2. While there are 2 or more items in the queue:
      a. Extract the two items with SMALLEST frequency: call them x and y.
      b. Create a new internal node z with freq = x.freq + y.freq.
      c. Set z.left = x, z.right = y.
      d. Insert z back into the queue.
  3. The last remaining item is the ROOT of the Huffman tree.
  4. Assign codes: left edge = 0, right edge = 1. Read from root to leaf for each symbol's code.

Minimum spanning tree highlighted

A spanning tree connects all V vertices with exactly V − 1 edges and no cycle. The minimum spanning tree (MST) has the smallest total weight. A graph that is not connected has no spanning tree. It has a minimum spanning forest, one tree per component. The 2022 paper asked this directly.

Cut property, the reason both algorithms are correct

Let A be a set of edges that is part of some MST. Take any cut of the vertices that no edge of A crosses. The lightest edge crossing the cut is safe: A plus that edge is still part of some MST.

Proof: let T be an MST containing A, and e the light edge. If e ∈ T we are done. Otherwise T + e has a cycle, which crosses the cut at another edge f. Since e is lightest across the cut, w(e) ≤ w(f). Then T' = T − f + e is a spanning tree with w(T') ≤ w(T), so it is also an MST and it contains A + e. ∎

Kruskal's algorithm

🟣 Beginner Explanation

Find the cheapest way to connect all cities (minimum spanning tree).
Kruskal's strategy: always add the cheapest edge that doesn't create a loop. It's like building a network cheaply — always pick the cheapest available cable, skip cables that would create a ring (redundant connection).

📋 Easy Step-by-Step AlgorithmEasy steps:
  1. Sort ALL edges by weight (cheapest first).
  2. Start with each vertex as its own "component" (no edges yet).
  3. For each edge (u,v) in sorted order:
      If u and v are in DIFFERENT components: add this edge to MST, merge their components.
      If u and v are in the SAME component: skip (would create a cycle).
  4. Stop when you have V-1 edges (MST complete).

How to check "same component"? Use DSU (Disjoint Set Union / Union-Find):
FIND(x) returns the "representative" of x's component.
UNION(x,y) merges the two components.
Different components iff FIND(u) ≠ FIND(v).

KRUSKAL(G)
A = empty set
for each vertex v: MAKE-SET(v)
sort edges by weight
for each edge (u, v) in that order
    if FIND-SET(u) != FIND-SET(v)      // different components, no cycle
        add (u, v) to A;  UNION(u, v)
return A

Disjoint-set union (DSU) and safe edges

Every vertex starts in its own set. An edge (u, v) is safe exactly when u and v are in different sets, because the set containing u defines a cut that no chosen edge crosses, and the edge is the lightest one seen that crosses it (edges come sorted). FIND returns the set's representative. UNION merges two sets after the edge is accepted.

With union by rank and path compression, m operations cost O(m α(n)), where α is the inverse Ackermann function, below 5 for any real input.

Kruskal total: sorting O(E lg E) = O(E lg V), plus O(E α(V)) for the set operations. Result O(E lg V). Without a DSU, checking for a cycle by search or relabeling costs O(V) per edge and the total grows to about O(E·V).

🟣 Beginner Explanation

Imagine you're a GPS finding the shortest road from your house to every other place in the city. You always visit the nearest unvisited place first, update distances to its neighbours, and never go back. It's like a wave spreading from the source — nearest places get finalised first.

📋 Easy Step-by-Step AlgorithmEasy step-by-step (memorise this table method):
  1. Set d[source] = 0, d[all others] = ∞. Mark all vertices as unvisited.
  2. Pick the unvisited vertex u with the smallest d[u] (this is the "nearest" vertex).
  3. Mark u as visited (it's now finalised — d[u] won't change).
  4. For each neighbour v of u: if d[u] + weight(u,v) < d[v], update d[v] = d[u] + weight(u,v). (This is called RELAXATION.)
  5. Repeat steps 2–4 until all vertices are visited.

Exam table format: Draw a table with columns = vertices, rows = each step. Fill in distances after each extraction.

Golden rule: Dijkstra ONLY works with NON-NEGATIVE edge weights. If there are negative edges, use Bellman-Ford.

Proof of correctness

Claim: when a vertex u is added to S, d[u] = δ(s, u), the true shortest distance.

Suppose u is the first vertex added with d[u] ≠ δ(s, u). Take a true shortest path from s to u. Let y be the first vertex on it that is not in S, and x the vertex before it, which is in S.

  1. d[x] = δ(s, x), since x was added before u. When x was added, edge (x, y) was relaxed, so d[y] = δ(s, y).
  2. Weights are non-negative, so δ(s, y) ≤ δ(s, u) ≤ d[u].
  3. The algorithm chose u over y, so d[u] ≤ d[y].
  4. Together: d[y] = δ(s, y) = δ(s, u) = d[u]. So d[u] = δ(s, u), a contradiction. ∎

Step 2 is where non-negative weights are needed. With a negative edge, a longer prefix can lead to a cheaper total, and the proof breaks.

🟣 Beginner Explanation

LCS = Longest Common Subsequence. Not substring! A subsequence can skip characters but must keep order.
Example: LCS of "ABCBDAB" and "BDCABA" is "BCBA" (length 4).
Think of it as: what's the longest sequence of characters that appears (in order, possibly with gaps) in BOTH strings?

📋 Easy Step-by-Step AlgorithmFill the table c[i][j] (row = X chars, col = Y chars):
  1. Row 0 and column 0: all zeros (empty string has LCS 0 with anything).
  2. For each i (row) and j (column):
      If X[i] == Y[j]: c[i][j] = c[i-1][j-1] + 1 (characters match → extend LCS by 1)
      Else: c[i][j] = max(c[i-1][j], c[i][j-1]) (take the better of skipping X[i] or Y[j])
  3. Answer = c[m][n] (bottom-right).
Traceback to find the actual LCS:
  1. Start at c[m][n].
  2. If X[i]==Y[j]: this character is IN the LCS. Move diagonally (i-1, j-1). Write down the character.
  3. Else: move to whichever neighbor is larger (up or left).

SCS (Shortest Common Supersequence) = m + n − LCS length.

Asked in 2022 (fill DP table), 2023 (fill table + traceback), 2024 (fill table + find ALL optimal solutions). This is GUARANTEED to appear. Know both filling AND traceback cold.

🟣 Beginner Explanation

Imagine you're packing a bag for a trip. You have items with weights and values. Your bag has a weight limit. Each item is either fully packed or left behind (0 or 1 — hence "0/1"). You want maximum value without overloading the bag. Greedy (just pick highest value/weight ratio) doesn't work here — DP does.

📋 Easy Step-by-Step AlgorithmBuild a 2D table dp[items][capacity]:
  1. Row 0 (no items) and Column 0 (capacity=0): all zeros.
  2. For each item i (row) and each capacity j (column):
      If item i is too heavy (w[i] > j): dp[i][j] = dp[i-1][j] (skip this item)
      If item i fits (w[i] ≤ j): dp[i][j] = max(dp[i-1][j], v[i] + dp[i-1][j - w[i]])
        = max(skip item i, take item i)
  3. Answer = dp[n][W] (bottom-right cell).
Traceback to find WHICH items were taken:
  1. Start at dp[n][W].
  2. If dp[i][j] ≠ dp[i-1][j]: item i was TAKEN. Move to dp[i-1][j - w[i]].
  3. If dp[i][j] == dp[i-1][j]: item i was SKIPPED. Move to dp[i-1][j].
  4. Repeat until i=0.

Memory trick: "Can I fit it? Then take the better of (skip it) vs (take it + best with remaining space)"

  • 2022: Capacity 10. Also compare 0/1 with fractional knapsack.

Critical distinction: Greedy by ratio fails for 0/1. Example: W=50, items (60,10),(100,20),(120,30). Greedy gives 160 (wrong). DP gives 220 (correct, items 2 and 3). Always use the DP table for 0/1.

Each item is taken whole or left out. This is the DP version that works where greedy fails.

Matrix chain multiplication (MCM) highlighted

🟣 Beginner Explanation

Multiplying matrices in different orders gives the same result but different costs.
(AB)C and A(BC) give the same answer, but (AB)C might need 1000 operations while A(BC) needs only 100.
MCM finds the CHEAPEST ordering of brackets. The cost of multiplying p×q by q×r = p×q×r operations.

📋 Easy Step-by-Step AlgorithmDP table approach:
  1. Let p[0..n] = dimension array (matrix i has size p[i-1]×p[i]).
  2. m[i][j] = minimum cost to multiply matrices i through j.
  3. m[i][i] = 0 (single matrix, no multiplication needed).
  4. Fill by increasing chain length l=2,3,...,n:
      For each i, set j = i+l-1.
      m[i][j] = min over k from i to j-1 of (m[i][k] + m[k+1][j] + p[i-1]×p[k]×p[j]).
  5. Answer = m[1][n].

Simple example: dims [10,20,30,40] → A1(10×20), A2(20×30), A3(30×40)
m[1][2] = 10×20×30 = 6000. m[2][3] = 20×30×40 = 24000.
m[1][3]: try k=1: m[1][1]+m[2][3]+10×20×40 = 0+24000+8000=32000. try k=2: m[1][2]+m[3][3]+10×30×40=6000+0+12000=18000.
Best = 18000 (bracket as (A1A2)A3).

Multiplying matrices is associative, so the order of the brackets does not change the answer, but it changes the cost. Multiplying a p×q matrix by a q×r matrix takes pqr scalar multiplications. Find the cheapest bracketing.

m[i][i] = 0 m[i][j] = min over i ≤ k < j of ( m[i][k] + m[k+1][j] + p[i−1]·p[k]·p[j] )
  • Matrix Aᵢ has size p[i−1] × p[i]. Fill the table by increasing chain length. Store the best split k in s[i][j].
  • Time Θ(n³), space Θ(n²).
  • Answer is m[1][n]. Rebuild the brackets from s.

Small example

Single-source shortest path: Bellman-Ford highlighted

🟣 Beginner Explanation

Like Dijkstra's GPS, but it can handle "negative roads" (e.g., a discount that makes the route cheaper). It's slower but more powerful. It also detects if there's a "negative cycle" — a loop that keeps getting cheaper forever, which means no true shortest path exists.

📋 Easy Step-by-Step AlgorithmEasy step-by-step:
  1. Set d[source] = 0, d[all others] = ∞.
  2. Repeat |V|-1 times (V = number of vertices):
      For EVERY edge (u, v) with weight w:
        If d[u] + w < d[v]: update d[v] = d[u] + w.
  3. Do one more pass. If any distance still decreases: NEGATIVE CYCLE detected!

Why |V|-1 times? The shortest path between any two vertices has at most |V|-1 edges (otherwise it would revisit a vertex = cycle). So after |V|-1 passes, all distances are correct.

Dijkstra vs Bellman-Ford:
Dijkstra = faster (greedy), but NO negative edges.
Bellman-Ford = slower O(VE), but handles negative edges and detects negative cycles.

⚠ 2023: Full Bellman-Ford trace + negative cycle detection

2023 exam: Run Bellman-Ford on a directed graph (graph was partially unreadable in scan). Show the distance array after each of the V−1 passes. Report whether a negative cycle is reachable from the source.

Key: After V−1 passes, if one more relaxation is still possible → negative cycle detected. Time: O(VE).

Handles negative edge weights and detects negative cycles. It is dynamic programming over the number of edges used.

BELLMAN-FORD(G, s)
for each vertex v: d[v] = infinity;  d[s] = 0
repeat |V| - 1 times
    for each edge (u, v) with weight w
        if d[u] + w < d[v]: d[v] = d[u] + w, parent[v] = u    // relax
for each edge (u, v)                                             // extra pass
    if d[u] + w < d[v]: return "negative cycle reachable from s"

Why it works

After pass i, every vertex whose shortest path uses at most i edges has the correct distance. Without a negative cycle a shortest path has at most V − 1 edges, so V − 1 passes are enough. If an edge can still be relaxed after that, some path keeps getting cheaper, which means a negative cycle. Time O(VE). If a pass changes nothing, stop early.

All-pairs shortest path: Floyd-Warshall highlighted 🔁 2 YEARS

🟣 Beginner Explanation

Dijkstra finds shortest paths FROM one source. Floyd-Warshall finds shortest paths BETWEEN ALL pairs of vertices. Imagine making a "distance table" for all cities — like a map app that shows shortest distance between any two cities.

📋 Easy Step-by-Step AlgorithmThe key idea (DP): For each "intermediate" vertex k, check if going through k makes any path shorter.
  1. Start with d[i][j] = direct edge weight (∞ if no edge, 0 if i=j).
  2. For k = 1 to n (try each vertex as an intermediate):
      For i = 1 to n:
        For j = 1 to n:
          d[i][j] = min(d[i][j], d[i][k] + d[k][j])

English: "Is the path from i to j shorter if we go through k?" If yes, update.

Detecting negative cycle: After the algorithm, check the diagonal. If d[i][i] < 0 for any i, there's a negative cycle through vertex i.

Time: O(V³) — three nested loops each running V times.

Visit every city exactly once and return to the start with minimum total cost. Brute force checks (n − 1)! tours. Bitmask DP (the Held-Karp method) shares work between tours.

📋 Easy Step-by-Step AlgorithmEasy backtracking algorithm:

  4. If not safe for any c: backtrack (return, let the caller try next column).

⚠ 2024: Exam scheduling as m-coloring, m=3

🟣 Beginner Explanation

Color the vertices of a graph so that no two connected vertices share the same color.
Real uses: exam scheduling (courses sharing students can't be at the same time), register allocation in compilers, map coloring (no adjacent countries same color).

📋 Easy Step-by-Step AlgorithmEasy backtracking algorithm:
  1. Try coloring vertex k with color c = 1, 2, ..., m.
  2. Check if safe: none of k's neighbors already have color c.
  3. If safe: assign color[k] = c, recurse for vertex k+1.
  4. If no color works: backtrack (all m colors clash → this path is a dead end).
  5. If k > n: found a valid coloring! Print it.

Rat in a maze highlighted

A rat starts at the top-left cell of an N × N grid and must reach the bottom-right cell. Cells marked 0 are walls. Backtracking tries each direction in turn. If none works from a cell, the rat steps back and tries another direction.

SOLVE(i, j)
if (i, j) is the goal: mark it on the path; return true
mark (i, j) visited and on the path
for each direction d in (D, R, U, L)
    (a, b) = neighbor in direction d
    if (a, b) is inside the grid, open, and not visited
        if SOLVE(a, b): return true
unmark (i, j) from the path                 // dead end, backtrack
return false
  • With a visited array each cell is entered at most once, so time O(N²). Without it, paths can loop and the search can run forever.
  • If only moves down and right are allowed, no visited array is needed, since the rat cannot return.

Solving Sudoku highlighted

Fill a 9 × 9 grid so each row, column and 3 × 3 box holds the digits 1 to 9 once. Backtracking fills the empty cells one at a time.

SOLVE(grid)
find an empty cell (r, c); if none: return true         // solved
for digit = 1 to 9
    if digit is not in row r, column c, or the 3x3 box of (r, c)
        grid[r][c] = digit
        if SOLVE(grid): return true
        grid[r][c] = 0                                   // undo, backtrack
return false                                             // no digit fits: dead end
  • Box of cell (r, c) (0-indexed): its top-left corner is (3·⌊r/3⌋, 3·⌊c/3⌋).
  • The bounding function is the row, column and box test. It prunes almost every branch. A cell with no legal digit is a dead end and forces backtracking.
  • Speed-up: choose the empty cell with the fewest legal digits first (minimum remaining values).
  • It is the same pattern as N-Queens: choose a cell, try values, test, recurse, undo.

Branch and bound

Branch and bound searches the same kind of state space tree as backtracking, but for optimization problems. It prunes a node when its bound shows that no solution below it can beat the best answer found so far.

Branch and bound in a state space tree highlighted

🟣 Beginner Explanation

Branch and bound is backtracking with a "budget check".
In backtracking, you abandon a path when it violates a constraint. In branch and bound, you also abandon a path when even the BEST POSSIBLE completion can't beat your current best answer. It's like house hunting — if you've already found a house for \$200k, you don't visit a neighbourhood where the cheapest house is \$300k.

📋 Easy Step-by-Step AlgorithmKey concepts:
  • BOUND: An optimistic estimate of the best solution reachable from a node (upper bound for maximization, lower bound for minimization).
  • PRUNE: If bound ≤ current best: skip this whole subtree.
  • FIFO B&B: Use a QUEUE. Explore level by level (like BFS).
  • LC (Least-Cost) B&B: Use a PRIORITY QUEUE. Always expand the node with the BEST bound first. Finds good solutions faster → prunes more.
For 0/1 Knapsack B&B:
  1. Sort items by profit/weight ratio.
  2. For each node, bound = current profit + greedy fill of remaining capacity (fractional knapsack).
  3. Branch: include item (left child) or exclude item (right child).
  4. Prune node if: bound ≤ best profit found, OR weight exceeds capacity.
  • Branching: split a node into children, each fixing one more decision.
  • Bounding: compute for each node an optimistic bound. For maximization it is an upper bound on any solution below the node. For minimization it is a lower bound.
  • Pruning: keep the best complete solution found so far. Discard a node whose bound is no better than that value.
  • Terms: a live node has been generated and not yet expanded. The E-node is the node being expanded. A dead node is pruned or fully expanded.

FIFO branch and bound highlighted

The list of live nodes is a queue. The oldest live node is expanded next, so the tree is explored level by level, as in breadth-first search. The bound is used only to prune.

LC (least cost) branch and bound highlighted

The list of live nodes is a priority queue. The node with the best bound (lowest cost estimate ĉ(x) for minimization, highest upper bound for maximization) is expanded next. The search heads for the most promising region first, finds a good solution early, and so prunes more nodes. A LIFO list gives a depth-first search instead.

0/1 knapsack as a worked example

Items (profit : weight) 10:2, 10:4, 12:6, 18:9, capacity 15. Sort by profit per weight. Each node decides one more item: include or exclude. The bound of a node is its profit plus a greedy fill of the remaining capacity, taking the last item fractionally. This is the fractional knapsack from the greedy chapter, which is always at least as good as any 0/1 completion, so it is a valid upper bound.

  • Prune a node if bound ≤ best profit so far, or if its weight exceeds capacity.
  • Update the best profit when a feasible node has a higher profit.

Travelling salesman by LC branch and bound: the reduced cost matrix

For a minimization problem the bound is a lower bound. For TSP, reduce the cost matrix: subtract each row's minimum from that row, then each column's minimum from that column. The sum of everything subtracted is a lower bound on any tour.

Matrix for 5 cities (∞ on the diagonal):

∞ 20 30 10 11 15 ∞ 16 4 2 3 5 ∞ 2 4 19 6 18 ∞ 3 16 4 7 16 ∞

Row minima are 10, 2, 2, 3, 4, which sum to 21. After subtracting, the column minima are 1, 0, 3, 0, 0, which sum to 4. Root lower bound = 21 + 4 = 25. The optimal tour for this matrix costs 28.

To expand a node for the edge i → j: set row i and column j to ∞, set the return entry j → 1 to ∞ to forbid a short cycle, reduce again, and add the reduction to the parent's bound plus cost[i][j]. Always expand the live node with the smallest bound. Prune nodes whose bound is at least the best tour found.

This course also lists bin packing in earlier papers (best fit and first fit as resource allocation). Those two are heuristics, not branch and bound. First fit puts each item in the first bin with room. Best fit puts it in the bin that leaves the least space.

Practice with answers

Try each on paper first, then open the answer.

1. Solve with the master method: (a) T(n) = 4T(n/2) + n (b) T(n) = 2T(n/2) + n lg n (c) T(n) = 3T(n/2) + n² (d) T(n) = T(n/2) + 1 (e) T(n) = 2T(n/2) + n/lg n (f) T(n) = 7T(n/2) + n²

Answer

(a) log₂ 4 = 2, f = n is smaller: Θ(n²). (b) log₂ 2 = 1, f = n lg n is case 2 with k = 1: Θ(n lg² n). (c) log₂ 3 ≈ 1.585 < 2, case 3. Regularity: 3(n/2)² = (3/4)n² ≤ c·n² with c = 3/4. Θ(n²). (d) log₂ 1 = 0, f = 1: case 2, Θ(lg n). (e) Master method does not apply (f is in the gap). Recursion tree: level i costs n/(lg n − i). Sum is Θ(n lg lg n). (f) Θ(n^(lg 7)).

2. Prove by substitution that T(n) = T(n−1) + n is O(n²).

Answer

Guess T(n) ≤ c·n². Assume it for n−1. Then T(n) ≤ c(n−1)² + n = cn² − 2cn + c + n. This is ≤ cn² when (2c − 1)n ≥ c. Take c = 1: need n ≥ 1, true. Base: T(1) = 1 ≤ 1·1² if T(1) = 1. So T(n) = O(n²).

3. Trace counting sort on A = [4, 1, 3, 4, 3] with k = 4. Show C after each phase and the output.

Answer

Counts C[0..4] = [0, 1, 0, 2, 2]. Prefix sums [0, 1, 1, 3, 5]. Right to left: A[5]=3 goes to B[3], C[3]=2. A[4]=4 to B[5], C[4]=4. A[3]=3 to B[2]. A[2]=1 to B[1]. A[1]=4 to B[4]. Output [1, 3, 3, 4, 4]. The two 3s kept their input order, which shows stability.

4. Trace radix sort on [170, 45, 75, 90, 802, 24, 2, 66].

Answer

Pad to 3 digits. After ones digit: 170, 090, 802, 002, 024, 045, 075, 066. After tens digit: 802, 002, 024, 045, 066, 170, 075, 090. After hundreds digit: 2, 24, 45, 66, 75, 90, 170, 802. Time Θ(d(n+k)) with d = 3, k = 10.

5. Prove that every comparison sort needs Ω(n lg n) comparisons.

Answer

Use the decision tree proof in the lower bound section. Write four lines: tree has at least n! leaves; height h satisfies 2ʰ ≥ n!; lg(n!) ≥ (n/2) lg(n/2); so h = Ω(n lg n). Marks usually go to the leaf count argument and the bound on n!.

6. How many comparisons do the pairs method and two separate scans use for n = 100 and n = 101?

Answer

Pairs: n = 100 gives 3·100/2 − 2 = 148; n = 101 gives 3·⌊101/2⌋ = 150. Two scans: 2(n−1) = 198 and 200.

7. Give an input that makes quicksort (last-element pivot) take Θ(n²), and show the recurrence.

Answer

Any already sorted array. The pivot is the maximum, so partition produces sizes n−1 and 0. T(n) = T(n−1) + Θ(n) = Θ(n²). All-equal keys do the same with Lomuto partition. Random pivot choice makes this unlikely for any fixed input.

8. Multiply 1234 × 5678 with Karatsuba (one level, B = 100). How many multiplications of two-digit numbers are used, against the schoolbook split?

Answer

Three: 12·56 = 672, 34·78 = 2652, 46·134 = 6164 (the last has up to 3-digit operand). z₁ = 2840. Result 7,006,652. The schoolbook split uses four.

9. State the recurrences and running times for plain and Strassen multiplication. How many scalar multiplications do they use for 8 × 8?

Answer

Plain: T(n) = 8T(n/2) + Θ(n²) = Θ(n³), 512 scalar multiplications. Strassen: T(n) = 7T(n/2) + Θ(n²) = Θ(n^(lg 7)), 7³ = 343 scalar multiplications.

10. Show that n increments of a binary counter cost O(n) in total.

Answer

Bit i flips ⌊n/2ⁱ⌋ times. Total flips = Σ ⌊n/2ⁱ⌋ < n·Σ 1/2ⁱ = 2n. Amortized cost per increment is O(1).

11. Why does median of medians use groups of 5, and what happens with groups of 3?

Answer

With 5, the recursive sizes are n/5 and at most 7n/10, adding to 9n/10 < 1·n, so the cost is linear. With 3, sizes are n/3 and 2n/3, adding to exactly n. The recurrence T(n) = T(n/3) + T(2n/3) + O(n) is Θ(n lg n), so linear time is lost.

12. When is bucket sort Θ(n) and when is it Θ(n²)?

Answer

Linear in expectation when inputs are uniformly distributed over [0,1), because buckets stay small (E[nᵢ²] = 2 − 1/n). Quadratic when most elements land in one bucket and insertion sort runs on that bucket.

13. Prove by loop invariant that the final placement loop of counting sort is correct and stable.

Answer

Invariant: before the iteration for index j (scanning from n down), for every value v, C[v] is one more than the last unused output slot for v, and all elements A[j+1..n] are already in their final slots. Initialization: after the prefix pass, C[v] is the count of elements ≤ v, the last slot for v. Maintenance: placing A[j] at C[A[j]] then decrementing keeps earlier copies at lower slots, so the rightmost duplicate takes the highest slot. Termination: all elements placed, equal ones in input order.

Master method in one breath

Compute c = log_b a. If f is polynomially smaller than nᶜ, answer Θ(nᶜ). If it matches (times lgᵏ n, k ≥ 0), answer Θ(nᶜ lg^(k+1) n). If it is polynomially larger and regular, answer Θ(f).
